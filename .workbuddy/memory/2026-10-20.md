# 2026-10-20

- 从零搭建 code-review-guru（本工作区）：Spring Boot 3.5.16 + spring-ai 1.1.8 + MyBatis 3.0.4 + 内嵌 H2（默认文件型 ./reviewdb / MODE=MySQL，测试用内存）+ Freemarker + Tailwind（提交产物）+ 零依赖 app.js。前端硬约束对齐 vela-web（CSP 零豁免、同源、无内联 onclick/style、无 eval）。
- 功能闭环：提交代码 → 规则/AI 评审 → 结构化 findings 落 review_request / review_finding → 首页 / 历史 / 详情三个 SSR 页面。
- 关键排坑（重要，详见 MEMORY.md）：
  1. spring-ai 1.1.8 的 OpenAI 各模型自动配置启动期强校验 api-key，缺 key 直接令 ApplicationContext 起不来。解法：application.yml 给占位 key `sk-local-placeholder` + `spring.autoconfigure.exclude` 排除 embedding/image/audio-speech/audio-transcription/moderation 五个配置，仅留 chat；是否真调 AI 由服务层按「非占位 key」判定（app.review.ai-enabled=auto），否则/异常回退 RuleBasedReviewer（离线可用，非伪造）。
  2. Spring Boot 只加载类路径第一个 application.yml；src/test/resources/application.yml 会整份遮蔽主配置，且 mvn test（非 clean）不清 target/test-classes 里的陈旧副本——一度让所有配置改动「看似无效」。测试改用 @DynamicPropertySource 只覆盖数据源，并删除测试 application.yml。
  3. SQL 拼接检测正则方向写反，改为「引号内含 SQL 关键字 + 同行有 +」。
- 门禁（真实跑通）：mvn clean test → BUILD SUCCESS，10/10（RuleBasedReviewerTest 5 + ReviewControllerIntegrationTest 5），MVN_EXIT=0。jar 冒烟：真起 jar，GET / 200、POST→302→详情页含 findings、响应头 CSP `script-src 'self'` 命中、静态资源同源 200、package_exit=0。
